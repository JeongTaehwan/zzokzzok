# 쪽쪽 — 모바일 앱 배포 가이드

Android(Google Play)와 iOS(App Store) **앱** 배포 절차. 이 저장소에서 자동으로 준비되는 것과, 스토어 계정이 있어야만 할 수 있는 일을 구분해 적었다.

---

## 0. 한눈에 보기

| 단계 | Android | iOS |
|---|---|---|
| 서명 키 | ✅ 준비됨 `android/keystore/zzokzzok-upload.jks` (git 제외) | Apple 개발자 계정에서 자동 관리(Xcode Automatic Signing) |
| 스토어 산출물 | ✅ `release/zzokzzok-0.1.0.aab` (Play 업로드용), `release/zzokzzok-0.1.0-release.apk` (직접 설치용) | Xcode Archive → App Store Connect 업로드 (macOS 필요) |
| 자동 빌드(CI) | ✅ `.github/workflows/android-release.yml` | ✅ `.github/workflows/ios-build.yml` (macOS 러너, 컴파일 검증) |
| 개인정보 처리방침 | ✅ `docs/privacy-policy.md` (공개 URL 필요) | 동일 |
| 개발자 계정 | Google Play Console (1회 $25) | Apple Developer Program (연 $99) |

## 1. Android — Google Play

### 1-1. 서명 키 (이미 생성됨)

```
android/keystore/zzokzzok-upload.jks   # 업로드 키 (RSA 2048, 10000일)
android/keystore.properties            # 비밀번호·별칭 (git 제외)
```

> ⚠️ **이 두 파일을 반드시 다른 곳(비밀번호 관리자, 외장 저장소)에 백업하세요.**
> 키를 잃어버리면 같은 패키지명(`com.zzokzzok.app`)으로 업데이트를 올릴 수 없습니다.
> Play App Signing 을 켜두면(기본값) Google 이 앱 서명 키를 보관하므로, 업로드 키를 잃어도 재설정 절차로 복구할 수 있습니다.

### 1-2. 릴리스 빌드

```bash
source scripts/android-env.sh
npm run android:release        # → release/zzokzzok-<버전>.aab, release/zzokzzok-<버전>-release.apk
```

- **AAB** 를 Play Console 에 올린다 (APK 는 Play 에서 받지 않음).
- **release APK** 는 스토어 없이 폰에 직접 설치해 최종 확인하는 용도.
- 버전 올리기: `android/app/build.gradle` 의 `versionCode`(정수, 매 업로드마다 +1) 와 `versionName`.

### 1-3. Play Console 절차

1. https://play.google.com/console → **앱 만들기**: 이름 `쪽쪽`, 기본 언어 한국어, 앱, 무료.
2. **앱 설정 → 대시보드** 의 필수 항목:
   - 개인정보 처리방침 URL: `docs/privacy-policy.md` 를 공개 URL 로 게시 (GitHub Pages, Notion 공개 페이지 등) 후 입력
   - 앱 액세스: 로그인 없음
   - 광고: 없음
   - 콘텐츠 등급: 설문 작성 (유틸리티, 폭력/성적 콘텐츠 없음)
   - 타겟층: 18세 이상 (양육자용) — 아동 대상 아님으로 답변
   - 데이터 보안: **데이터 수집 안 함** 선택 (앱은 서버 통신 없음)
   - 앱 카테고리: 육아 (Parenting)
3. **스토어 등록정보**: 짧은 설명(80자), 전체 설명, 스크린샷(폰 최소 2장, `docs/screenshots/` 사용 가능, 1080×1920 권장), 앱 아이콘 512×512 (`assets/icon-only.png` 리사이즈), 그래픽 이미지 1024×500.
4. **프로덕션 → 새 버전 만들기** → `release/zzokzzok-0.1.0.aab` 업로드 → 출시 노트 → 검토 제출.
   - 처음엔 **내부 테스트** 트랙으로 올려 본인 계정에서 설치 확인하는 것을 권장.
5. **정확한 알람 권한(`USE_EXACT_ALARM`) 관련**: Play 정책상 알람/타이머가 핵심 기능인 앱만 사용 가능. 검토 시 "수유 타이머/알람 앱으로, 설정한 시각에 정확히 알림을 울리기 위해 필요" 라고 기재. (거절되면 `USE_EXACT_ALARM` 을 매니페스트에서 제거하고 `SCHEDULE_EXACT_ALARM` 런타임 요청만 사용 — 앱에 이미 "정확한 알람 허용하기" 버튼이 구현되어 있음.)

### 1-4. Play 대상 API 레벨

현재 `targetSdkVersion = 36` (`android/variables.gradle`). Google 은 매년 8월 말 신규 앱의 최소 대상 API 를 올리므로 제출 전 [정책 페이지](https://developer.android.com/google/play/requirements/target-sdk) 확인.

## 2. iOS — App Store

Apple 은 iOS 앱 빌드/서명을 **macOS + Xcode** 에서만 허용한다. 이 저장소의 `ios/` 프로젝트는 완성되어 있으며, Mac 에서 아래만 하면 된다.

### 2-1. 준비 (Mac)

```bash
# Xcode (App Store), CocoaPods 설치 후
git clone https://github.com/JeongTaehwan/zzokzzok.git && cd zzokzzok
npm install
npm run ios:sync            # 웹 빌드 + ios 동기화 (pod install 포함)
npx cap open ios            # Xcode 열기
```

### 2-2. Xcode 설정 (최초 1회)

1. **Signing & Capabilities** → Team 선택 (Apple Developer 계정), *Automatically manage signing* 체크.
   Bundle Identifier 는 `com.zzokzzok.app` (App Store Connect 에서 같은 ID 로 앱 등록).
2. **General** → Display Name `쪽쪽`, Version `0.1.0`, Build `1` (이미 설정됨).
3. 기기 세로 고정, 앱 아이콘/스플래시, `PrivacyInfo.xcprivacy`(개인정보 매니페스트) 는 이미 포함됨.

### 2-3. 실기기 테스트 → TestFlight → 심사

1. 아이폰을 연결하고 ▶ 실행 → 알림 권한 허용 → 수유 종료 후 앱을 닫고 알림이 오는지 확인.
2. **Product → Archive** → Organizer 에서 **Distribute App → App Store Connect → Upload**.
3. https://appstoreconnect.apple.com → 앱 만들기(이름 쪽쪽, 번들 ID, SKU `zzokzzok`) → **TestFlight** 에서 본인/가족 초대해 테스트.
4. **App Store 탭**: 스크린샷(6.7", 6.5" 필수), 설명, 키워드, 지원 URL, **개인정보 처리방침 URL**, 앱 개인정보(데이터 수집 안 함), 연령 등급(4+), 카테고리(의료 또는 라이프스타일).
5. 빌드 선택 → **심사 제출**. 통상 1~3일.

### 2-4. Mac 이 없을 때

- GitHub Actions 의 `ios-build.yml` 이 macOS 러너에서 프로젝트를 컴파일해 **빌드가 깨지지 않았는지** 검증한다(서명 없음).
- 서명·업로드까지 클라우드에서 하려면 Apple 인증서(.p12)와 프로비저닝 프로파일을 GitHub Secrets 로 넣고 `xcodebuild -exportArchive` + `xcrun altool`/`fastlane deliver` 단계를 추가한다. (또는 Codemagic / Ionic Appflow 같은 서비스 이용 — 이 저장소 구조 그대로 연결 가능.)
- 그때까지는 아이폰 Safari 에서 웹 빌드를 열고 **홈 화면에 추가** 로 앱처럼 쓸 수 있다(앱이 열려 있을 때만 알람).

## 3. GitHub Actions (자동 빌드)

| 워크플로 | 트리거 | 결과 |
|---|---|---|
| `android-release.yml` | `v*` 태그 푸시 또는 수동 실행 | 테스트 → 서명된 AAB/APK 빌드 → Actions 아티팩트 + GitHub Release 첨부 |
| `ios-build.yml` | `main` 푸시/PR, 수동 실행 | macOS 러너에서 Xcode 빌드(서명 없음)로 iOS 프로젝트 검증 |

Android 서명을 CI 에서 하려면 저장소 **Settings → Secrets and variables → Actions** 에 등록:

```
ANDROID_KEYSTORE_BASE64   # base64 -w0 android/keystore/zzokzzok-upload.jks
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS         # zzokzzok
ANDROID_KEY_PASSWORD
```

```bash
# 로컬에서 시크릿 값 만들기
base64 -w0 android/keystore/zzokzzok-upload.jks
cat android/keystore.properties
```

시크릿이 없으면 워크플로는 서명되지 않은 빌드만 만든다.
