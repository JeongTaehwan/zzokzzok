# 쪽쪽 — 배포 가이드 (Expo / EAS)

Expo 프로젝트라서 **Mac 없이도** 아이폰·안드로이드 빌드를 Expo 클라우드(EAS)에서 만들 수 있다.
단계는 세 가지: ① Expo Go 로 바로 테스트 → ② 앱 파일(APK / iOS) 뽑아서 주변에 배포 → ③ 스토어 제출.

---

## 0. 한눈에 보기

| 목적 | 방법 | 필요한 것 |
|---|---|---|
| 내 폰에서 바로 테스트 | `npm run start:tunnel` → QR 을 Expo Go 로 스캔 | 폰에 Expo Go 앱 |
| 친구들도 Expo Go 로 열기 | `eas update` (클라우드에 번들 게시) → QR/링크 공유 | Expo 계정(무료) |
| 안드로이드 설치 파일 | `npm run build:android:apk` → APK 링크/QR | Expo 계정 |
| 아이폰 설치 (TestFlight) | `npm run build:ios` → `eas submit` → TestFlight 초대 | Apple 개발자 계정($99/년) |
| 아이폰 설치 파일(Ad Hoc) | `eas build -p ios --profile preview` + 기기 UDID 등록 | Apple 개발자 계정 |
| 스토어 | `eas build --profile production` → `eas submit` | Play Console($25) / App Store Connect |

> ⚠️ 아이폰은 애플 정책상 **개발자 계정 없이는 어떤 방법으로도 설치 파일을 나눠줄 수 없다.** 계정 전까지는 Expo Go 로 공유한다.

## 1. Expo Go 로 테스트 / 공유

### 1-1. 내 PC 에서 바로 (개발 서버)

```bash
npm run start:tunnel      # WSL/다른 네트워크에서도 폰이 접속되도록 터널
```

터미널 QR 을 **Expo Go** 로 스캔 (아이폰은 카메라 앱으로도 됨). PC 가 켜져 있는 동안만 열린다.

- `start:tunnel` 은 cloudflared 터널(계정 불필요)을 쓴다. WSL 은 폰이 LAN 주소(172.x)로 못 들어오므로 `npm start` 대신 이걸 쓴다. Expo 기본 터널(`expo start --tunnel`, ngrok)은 익명 세션이 거부될 수 있다.

### 1-2. PC 없이도 열리게 (EAS Update)

```bash
npx eas-cli login                       # 최초 1회
npx eas-cli init                        # 프로젝트 ID 발급 (app.json 에 기록됨)
npx eas-cli update --branch preview --message "v0.2.0"
```

출력되는 **QR / 링크**를 공유하면 친구들이 Expo Go 로 열 수 있다. 코드를 고치고 다시 `eas update` 하면 같은 링크가 최신으로 바뀐다.

## 2. 앱 파일 만들기 (EAS Build)

```bash
npx eas-cli login
npx eas-cli init            # 최초 1회 (app.json 에 extra.eas.projectId 기록)
```

### 2-1. 안드로이드 APK (주변 사람에게 직접 배포)

```bash
npm run build:android:apk          # (A) EAS 클라우드: eas build -p android --profile preview
npm run build:android:apk:local    # (B) 이 PC 에서: expo prebuild + Gradle (Expo 계정 불필요)
```

(B) 는 `credentials/zzokzzok-upload.jks` 로 서명한 `release/zzokzzok-<버전>.apk` 를 만든다. 첫 빌드는 의존성 다운로드 때문에 10~20분, 이후는 몇 분.
같은 키를 `credentials.json` 에도 넣어 두었으니 EAS 로 옮길 때 `eas credentials` 에서 "local credentials" 로 그대로 쓸 수 있다.

- 5~15분 뒤 완료되면 **다운로드 링크 + QR** 이 나온다. 친구들은 링크를 폰에서 열어 설치("출처를 알 수 없는 앱" 허용).
- 서명 키는 EAS 가 만들어 보관한다(`eas credentials` 로 확인/백업).
- 버전 올리기: `app.json` 의 `version`, `android.versionCode`.

### 2-2. iOS (TestFlight 로 배포)

```bash
npm run build:ios            # eas build -p ios --profile production
npx eas-cli submit -p ios    # App Store Connect 업로드 → TestFlight
```

- 처음 실행하면 Apple ID 로그인 → 인증서/프로비저닝을 EAS 가 자동 생성한다 (Mac 불필요).
- App Store Connect → TestFlight → **외부 테스터** 그룹에 이메일로 초대(최대 10,000명). 초대받은 사람은 TestFlight 앱에서 설치.
- 스토어 심사 없이 90일 동안 유효, 새 빌드를 올리면 갱신.

### 2-3. iOS Ad Hoc (.ipa 파일 직접 전달)

```bash
npx eas-cli device:create    # 친구 아이폰 UDID 등록 (링크를 보내 프로필 설치)
npx eas-cli build -p ios --profile preview
```

등록된 기기(연 100대)에서만 열리는 .ipa 가 나온다. 일반적으로는 TestFlight 가 더 편하다.

## 3. 스토어 제출

### Google Play
1. `npm run build:android:store` → AAB
2. https://play.google.com/console 에서 앱 만들기 → 개인정보 처리방침 URL(`docs/privacy-policy.md` 를 공개 URL 로 게시), 데이터 보안(수집 안 함), 콘텐츠 등급, 스크린샷
3. `npx eas-cli submit -p android` 또는 Console 에 AAB 업로드 → 내부 테스트 → 프로덕션
4. 대상 API: EAS 가 SDK 기본값(현재 API 36)을 사용

### App Store
1. `npm run build:ios` → `npx eas-cli submit -p ios`
2. App Store Connect → 앱 정보(이름 쪽쪽, 번들 ID `com.zzokzzok.app`), 스크린샷(6.7"), 설명, 개인정보 처리방침 URL, 앱 개인정보(수집 안 함), 연령 4+
3. 빌드 선택 → 심사 제출 (1~3일)
